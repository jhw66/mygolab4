# RabbitMQ 文件清理改造进度

## 第一批：文件基础能力

本批实现文件路径校验、随机唯一命名和幂等删除，尚未切换到异步清理。当前路径使用普通 `string`，不引入 `FileKey` 结构体或专门存储接口。

- `pkg/storage/key.go` 集中定义根目录与文件相对路径的不同校验规则。
- `NewLocalStore` 仅接受程序当前工作目录下的 `static` 或对应绝对路径；校验在创建目录之前完成，不自动寻找项目根目录，也不只比较目录末级名称。
- 相对路径严格接受 `video/<文件名>`、`cover/<文件名>`、`avatar/<文件名>`，公开地址仍为 `/static/<相对路径>`。不先清理文件相对路径来掩盖 `..`，磁盘路径中的原始 `..` 段也在归一化前拒绝。
- 新上传使用 `crypto/rand` 生成 128 位随机名，使用 `O_CREATE | O_EXCL` 创建，避免同秒上传覆盖。已有秒级文件名继续兼容。
- 每个存储实例固定绝对根目录，文件操作使用 Go 1.25 的 `os.Root`；删除拒绝目录、符号链接和越界路径，文件不存在视为成功。
- `pkg/utils/file.go` 保留现有上传、替换和删除函数签名，内部转到受管存储。现有 API 地址及表字段不变；返回的磁盘路径改为绝对路径，现有调用只用它做失败清理和日志。
- 兼容工具按本批约定使用工作目录下的 `./static`，每次调用后关闭存储句柄；现有 `NewLocalStore(filepath.Dir(filepath.Clean(dir)))` 构造调用不变。
- 上传、打开、删除及两类路径转换入口复用受管路径校验，直接调用 `Remove` 也不能绕过目录限制。
- 当前代码未包含 `FileReferenceRepo` 或数据库有效引用查询；本批的路径校验不代表已提供数据库引用保护，后续消费者仍需补齐该能力。

第一批完成后，业务仍按原时机同步清理文件，视频删除中的数据库与文件回滚问题尚待第三批解决；后续请求立即失效的数据库校验在第四批接入。

### 验证

在 PowerShell 中使用工作区可写缓存运行：

```powershell
$env:GOCACHE = Join-Path (Get-Location) 'tmp/go-cache'
go test ./pkg/storage ./pkg/utils -v
go test . ./internal/... ./pkg/...
```

所有测试媒体与目录均在临时工作目录内创建。覆盖根目录拒绝且不创建错误目录、三类正常上传、同名并发上传、确定性撞名重试、失败写入清理、旧文件保护、非受管路径与原始 `..` 拒绝、重复删除、工作目录变更后根目录固定、以及原有上传/替换/删除入口兼容。

2026-10-22 验证结果：上述相关测试和项目主包、核心包检查通过。共 13 个顶层用例通过，符号链接删除用例因 Windows 缺少创建符号链接权限跳过。正常上传、32 个同名并发上传、错误根目录无创建、非法路径保留目标内容及失败写入清理均已实际验证；测试未操作项目真实媒体文件。
